# 统一插件平台 v1：实施与验收基线

日期：2026-11-03。状态：内部市场与 Agent 的源码实现和隔离本地验收已完成；服务器部署、生产信任根及日常客户端发版未执行。以下工作包保留为完整目标，实际证据与能力边界见本节。

## 1. 实施原则

按照 [架构](../ARCHITECTURE.md) 与 [契约](SPEC-plugin-platform-v1.md) 实现完整系统。分批交付验证接缝，不削减最终合同。未完成执行器只能明确返回不支持，不能在 UI 上提前承诺。

本次包含共享库、服务端、管理后台、Core、Go 壳与桌面页面改造。市场保持内部权限控制；不变更生产配置或替换日常客户端。

完整命令范围与结果见 [本地验收记录](VERIFICATION-20261103.md)。

## 当前实现证据与边界

- 共享 Rust 工作区通过测试与 Clippy `-D warnings`；严格包校验、兼容/目标选择、依赖事务、激活失败回滚、崩溃恢复、配置 Schema、数据迁移和时间回拨保护有针对性测试。
- 真实隔离 PostgreSQL + 服务测试覆盖内部成员、发布审核/签名、下载授权、跨主体拒绝、撤销和临期续签。
- 真实 HTTP + 独立 Core stdio 进程覆盖：签名制品安装、Skills 实际调用、WASM 实际执行、MCP 审批与 echo 调用、私有页面数据、无 bearer 的离线重启恢复、启停 generation 递增、旧端口拒绝、安全撤销及卸载后移除技能/工具。
- 桌面桥和账户回归通过；新增账户测试验证身份绑定、短期市场凭据不落盘、缓存身份无 bearer、退出后不能恢复。
- 新页面及桥接测试通过；浏览器在 360/1080、浅色/深色验证安装确认和真实 iframe 隔离、消息端口私有存储、关闭销毁。前后端生产构建通过，pro 组合编译通过。
- DTO 与 Rust 消费快照由脚本生成并检查摘要。旧 source/name 正式安装 RPC 已拒绝；旧 SQL 和数据不删除、不自动上架。

macOS 原生夹具验证了主页面凭证、子 frame 消息和导航封闭；未验证平台不声明页面执行器。

当前产品实际支持用户 scope、Skills、受信本机 MCP、固定 HTTPS MCP、无 WASI 的 WASM Component 和隔离页面。普通配置使用包内 Schema，同版本也可经重新确认更新配置和选定模块；页面私有 JSON 数据支持纯组件迁移。没有验证的 sandboxed-process、服务器远程执行、OAuth/秘密代理和跨插件导出调用不在 Agent 能力声明中，要求相应能力时明确拒绝。这些扩展点不会要求未来产品复制市场或更换插件身份规范。

尚未执行：测试服务器部署、生产密钥仪式与信任根注入、服务器历史数据盘点、实际安装包升级/日常客户端验收，以及新 EOS 产品接入。不能把本地夹具标为正式插件或生产上线证据。

## 2. 工作包与依赖

### A. 规范与共享合同

归属：`eos-plugins`。

- Schema、标准解析器、能力目录、错误码、HostDescriptor、发布元数据及消息 DTO。
- Rust/TypeScript SDK 与 Go 桥接合同，固定版本依赖；不得维护三份手写字段真相。
- 标准正反例、依赖图与兼容判定夹具，声明生成流程与契约升级策略。
- `.eos-plugin` 打包器、制品清单、固定资源/SBOM 和离线校验。

完成条件：同一个包与 HostDescriptor，在服务端、Core 与 Web 策略模块得出同一兼容结果和错误码；所有无效包在执行前拒绝。

### B. 通用市场与内部控制

依赖 A。归属：base + pro 组合。

- base：插件/发布/目标/频道/ACL/撤销/验证模型、新 SQL 迁移、受控下载、管理流程。
- pro：EOS 官方发布者与应用注册、内部受众策略；沿用基座鉴权、限流、审计和权益接口。
- 发布验证/扫描工作进程、TUF 签名与轮换、私有存储及缓存分区。
- 管理后台：插件目录、清单检查、制品/来源、审查、发布/下架/撤销、频道和兼容性查看。

完成条件：无权用户不能经列表、详情、resolve、信任元数据、包、静态资源或缓存枚举内部插件；发布固定字节，撤销和频道并发控制有证据。

### C. 共享运行管理器

依赖 A；市场可先用合同测试服务模拟。

- 策略与兼容引擎、依赖求解、精确计划、权限差异、摘要绑定确认。
- 内容寻址缓存、作用域安装记录、事务日志、generation、锁与崩溃恢复。
- 能力代理、受限资源句柄、数据/配置/凭据接口、撤销与租约。
- 生命周期协调和错误/诊断输出。

完成条件：安装/升级任一步骤中断均恢复到可解释状态；没有半注册贡献或旧账户句柄泄露；幂等以业务状态验证。

### D. Agent 第一个完整宿主

依赖 B、C。

- Core 嵌入共享管理器，复用现有 MCP、Skills、审批和工具调用。
- 重做 name/source 驱动的市场安装接口，串通 Rust DTO、Go 桥接和前端。
- 用户界面覆盖发现/详情/兼容性/模块选择/授权/进度/已安装/升级/停用/卸载/诊断。
- 以独立 Dev 配置和数据验证，不覆盖日常客户端。

完成条件：从内部账号进入市场到安装、实际调用、重启恢复、升级、拒绝新权限、停用和卸载的完整闭环均由真实 Agent 验证。

### E. 隔离执行与 Web 宿主适配

依赖 C，与 D 可按模块推进。

- skills、MCP stdio/http、WASM Component、隔离 Webview 的完整执行器合同。
- 明确本机 `trusted-process` 与经过实际 OS 验证的 `sandboxed-process` 能力矩阵；后者无实现的平台保持拒绝。
- Web 宿主 SDK 复用同源策略；隔离资源加载、消息协议、CSP/导航与原生桥封闭。
- 后台页面插件模板迁入同一包规范和隔离视图，不再全局注入宿主框架。

完成条件：Agent 和一个真实可运行的 Web 参考宿主均加载同一发布的通用插件；差异由能力与执行器描述解释，而非复制两套特殊处理。

### F. 迁移与发布准备

依赖 A–E。

- 只读盘点实际数据库、本地插件、相关 MCP/Skills 注册和后台模板引用。
- 按盘点编写显式迁移工具，提供干跑、冲突清单、备份及回滚演练。
- 将静态索引示例隔离为开发夹具，不能当作已审核市场内容。
- 同一完整服务端产物先测试环境验收，再按独立发布授权安排生产；保留 base/pro 两个 SHA、制品清单和可执行回滚。
- 客户端发布单独验收；安装包、签名、Core 能力目录与实际调用一致才算交付。

完成条件：单一合同运行，无双格式/旧实现 fallback；原有无关账户、订单、应用和数据不受影响。生产推广与公开市场不是设计任务隐含授权。

## 3. 必须跑通的验收旅程

1. **内部可见**：匿名、普通外部账号、内部账号和管理员逐个验证目录/详情/包/资源；外部查不到内部身份和摘要。
2. **通用接入**：同一 ID、同一发布摘要在 Agent 与 Web 参考宿主上运行；不依赖各自私有路由、DOM 或 UI 框架。
3. **应用专属**：只允许指定应用的插件在其他应用明确拒绝；伪造请求中的 applicationId 不提升服务端访问权。
4. **能力协商**：匹配、缺失、版本冲突、可选模块不可用、执行器/OS 不支持、目标歧义均显示精确原因。
5. **实际功能**：测试技能确实可被发现并调用、MCP 工具实际响应、WASM 执行、UI 插槽显示且退出后销毁；不能只验安装返回值。
6. **隔离**：插件 A 不能读取 B 的数据/凭据，应用间与用户间均隔离；共享包缓存不带共享授权。
7. **升级授权**：升级新增写权限、扩大资源、改成本机受信或远程执行时重新确认；拒绝后旧安装仍可用。
8. **固定制品**：确认期间频道变化只能安装原计划字节；撤销/策略变化使计划失效，不能确认一个版本安装另一个。
9. **事务恢复**：下载/校验/注册/迁移/切换/激活/停用各步骤杀进程、断网或磁盘满，重启后无残留且状态正确。
10. **安全撤销**：在线、离线有效租约、租约过期、依赖者、时间回拨、回滚均符合合同，不宣称离线即时撤销。
11. **卸载**：退出 MCP、移除 Skills/UI/订阅、停止后台任务、撤销句柄；保留数据与清除数据选择分别验证。
12. **真实边界**：受信进程显示真实本机权限；要求 sandbox 的包在不支持环境拒绝；浏览器不静默执行到服务器。

## 4. 测试维度

由已审阅的规格生成用例，不按实现分支机械补断言。

- **等价类/边界**：ID、SemVer、Schema 修订、包大小/文件数/路径、资源作用域、Unicode/大小写碰撞。
- **状态机**：合法/非法安装转移、重复确认、重复发布、撤销后启用、离线恢复、卸载依赖。
- **错误注入**：签名不符、哈希不符、旧快照、过期元数据、损坏包、权限库不可用、执行器启动失败。
- **时序/竞态**：双安装、并发升级、账户切换中回调、撤销与激活竞争、迟到消息、窗口销毁、崩溃重放。
- **数据形态/安全**：malformed TOML、超大消息、未声明方法、SSRF/DNS 重绑定/跳转、目录逃逸、原生桥访问、凭据日志。

事务与竞态新增用例连续运行至少 5 次。核心回归断言完整业务状态、资源注册和实际副作用；不能只断言返回字段存在或“没有崩溃”。

## 5. 参考宿主与插件夹具

不为尚未存在的 EOS 产品编造接入结果。提供以下本地合成材料，全部显式标注为测试：

- portable Skills 插件及可选隔离面板。
- 一个版本化 WASM 能力插件。
- 一个固定运行资源的受信 MCP 插件，以及要求 sandbox 的拒绝/支持用例。
- targeted 任务接口插件与假业务服务，仅验证能力合同。
- Web 参考宿主：不捆绑完整 Agent，只实现必要 SDK、能力与插槽。
- 恶意包与跨实例越权夹具，网络使用受控测试服务。

真实 Agent + Web 参考宿主验证说明架构具备异构宿主接入能力；未来 Todo/Mail 等实际产品仍各自验收，不用参考宿主代替产品接受标准。

## 6. “完整平台完成”的判定

以下全部具备证据才可宣称完成：

- 同源规范、打包校验、SDK 和契约夹具已发布为固定内部版本。
- 内部目录、全路径访问控制、固定制品、签名/轮换/撤销可用。
- 共享管理器的升级、授权、隔离和恢复通过故障测试。
- Agent 实际调用与重启恢复通过，至少一个异构参考宿主通过。
- 每类声称支持的执行器均实际验收；未支持平台正确拒绝。
- 无旧合同双读、全局 JS 注入、浮动网络安装或权限确认换包。
- 新宿主可依接入文档独立完成：注册应用 → 引入 SDK → 提供 Adapter → 声明能力 → 跑符合性测试 → 接入同一市场。

设计文件存在、编译通过、后台能上传或 UI 显示“已安装”，均不足以单独证明上述完成。
